# MLCC 결함 사진 분석으로 옮길 교훈 (DAKER 미세구조 경도 대회 실험 근거)
목표: 결함 라벨이 아니라 **데이터(이미지 자체 특성) 기준**으로 정렬·군집해서 라벨 노이즈·도메인 편차를 찾고, 평가 신뢰도를 높이는 것. (MLCC 원본 데이터는 이번 작업에서 접근하지 않음. 아래 절차는 이번 대회 실험에서 나온 근거를 바탕으로 한 설계안.)

## 0. 한 줄 요약
- 모델을 바꿔도(Ridge, KRR, SVR, GP, DINOv2, CNN 미세조정) **같은 샘플을 같은 방향으로 틀리면** 튜닝 문제가 아니라 *표현(특징)에 정보가 없거나 라벨/생성 과정이 다르다*는 신호다. → 모델 교체 전에 데이터 진단부터.

## 1. 이미지 품질 지표로 먼저 정렬한다 (라벨 보기 전에)
근거: 이번 대회에서 흐린 사진 RMSE 15.5 vs 선명 12.6. 흐림-경도 상관은 0.1로 무관했지만 오차는 흐린 쪽에 몰렸다. 품질은 "라벨과 무관한 방해 요인이지만 오차를 키우는 요인"이었다.
절차:
1. 이미지마다 독립 계산(라벨·다른 이미지 통계 불사용): 선명도(Laplacian 분산), 잡음 σ(웨이블릿 MAD, `skimage.restoration.estimate_sigma`), 대비(블러 후 std, 1–99 분위 폭), 평균 밝기, 기울기 크기(다중 블러 스케일 σ=0,1,2,4,8).
2. 각 지표로 정렬해 상·하위 5%를 눈으로 본다(갤러리 HTML). 촬영 장비/로트/배율 차이가 여기서 먼저 드러난다.
3. 품질 지표와 라벨의 상관을 확인: 무관해야 정상. 상관이 크면 (a) 품질이 결함과 진짜 연결돼 있거나 (b) 특정 라인/장비에서 결함이 많이 찍힌 **도메인 혼입**이다. 이번 대회에선 원시 대비(std)가 경도와 0.44 상관 → '방해 요인'이라던 대비가 사실 2상 대비를 담고 있었다. 즉 "품질 지표"도 내용 정보를 섞어 갖는지 반드시 분리 확인.
4. **흐린 이미지를 빼지 않는다.** 이번엔 흐린 사진을 다 빼면 43% 손실이었고 test에도 같은 비율로 있다. 대신 품질층(3~5분위)별 성능을 따로 보고한다.

## 2. 품질층화 평가 (stratified reporting)
- 전체 지표 하나 대신 [품질 분위 × 라벨 구간] 표로 오차를 낸다. 이번 대회: 전체 13.9인데 고경도(>230, 18장) 편향 −31, 저경도(<170) +20. 평균 지표만 봤으면 놓쳤다.
- MLCC: [선명도 분위 × 결함 유형 × 라인/로트]별 재현율·정밀도. 특정 칸에서만 성능이 무너지면 그 칸이 도메인 편차 또는 라벨 노이즈 후보.

## 3. 엄밀 중첩 CV (낙관 편향 제거)
근거: 하이퍼파라미터와 블렌드 가중을 같은 OOF로 고르면 13.44로 보였으나 중첩으로 다시 재면 13.6 → 낙관 0.15~0.2. 반면 엄밀 CV 13.41 → 실제 Public 12.52로, 엄밀 CV는 믿을 만했다.
절차: outer KFold(5)×3 seeds, inner KFold(5)에서 정규화 강도·블렌드 가중 선택. 같은 웨이퍼/칩/로트/촬영 세션은 **같은 fold에 묶는 GroupKFold**(이미지 단위 누수 방지; 크롭 학습 시 같은 원본 크롭은 같은 fold). 개선 판정은 반복별 차이의 t값(예: t<−2)과 15개 fold 중 이긴 횟수로 한다(이번 크롭 블렌드 −0.06, t=−0.95, 11/15 → 채택 보류가 맞음).

## 4. 오차가 같은 샘플에 몰리는 패턴 진단
절차:
1. 서로 다른 계열 모델 3개 이상(측정 특징+선형, 임베딩+선형, 비선형/미세조정)의 OOF 잔차를 모은다.
2. 잔차 간 상관이 높고(>0.7) 같은 샘플에서 크면 → "공통 실패 집합".
3. 공통 실패 집합을 잔차 크기 순으로 갤러리화하고, **예측값은 같지만 정답이 맞은 샘플과 짝지어** 나란히 본다(이번: 예측 ~210인데 정답 250인 시편 vs 예측·정답 ~210 시편 → 결정립이 크고 길쭉함이 눈에 보였음).
4. 공통 실패 집합에 대해: (a) 라벨 재확인(MLCC는 재판정 요청) (b) 품질층 분포 확인 (c) 새 측정 특징 가설.
5. 하지 말 것: 공통 실패 샘플에 가중치 올리기. 이번에 고경도 가중 → 전체 13.6→16.3 악화. 가중·isotonic·예측 확장 모두 무효.

## 5. 측정 특징 vs 범용 임베딩
근거: 직접 만든 재료 지표(2상 분율·덩어리 크기·정렬도·교차수)+텍스처만으로 13.90, DINOv2 단독 13.97 → 측정 특징이 대형 모델과 대등. 둘을 섞으면 13.41(서로 다른 정보). CNN 미세조정(ResNet34 14.07, ConvNeXt-T 14.54)은 500장에서 과적합.
교훈: 데이터 수백~수천 장이면 **동결 임베딩 + 선형** 과 **도메인 측정 특징**의 블렌드가 미세조정보다 안전. 측정 특징은 이미지별 상대 기준(이미지 자체 중앙값·표준편차로 z화)이 절대 밝기보다 강했다(+0.52 vs +0.1~0.3) → MLCC에서도 밝기/대비가 장비마다 다르면 이미지별 정규화 후 측정.
비선형(KRR/SVR/GP)으로 바꿔도 같은 특징에서 이득 0 → 특징이 정보 상한을 정한다.

## 6. 증강·불변성
- 물리적으로 경도/결함 판정과 무관한 변환만 증강/TTA: 이번엔 D4(회전 90°×뒤집기) 8방향 평균. "절대 방향 무관, 정렬 정도만 중요"라는 주최 힌트와 일치.
- MLCC: 단면 방향이 의미 있으면(적층 방향) 회전 불변을 쓰면 안 됨 → 뒤집기만. 증강 전에 "이 변환에 라벨이 바뀌는가"를 도메인 지식으로 표로 만든다.
- 디노이즈(NLM)는 DINOv2 입력을 오히려 망침(14.90) → 전처리는 모델별로 검증, 일괄 적용 금지.

## 7. 데이터 기준 군집으로 라벨 노이즈·도메인 편차 찾기 (절차안)
1. 특징 3종 준비: (a) 품질 지표 (b) 구조 측정 지표 (c) 동결 임베딩(DINOv2-S/B, CLS+패치평균, D4 평균).
2. 각 공간에서 표준화 → UMAP/PCA 2D + HDBSCAN 군집. 군집마다 품질·라인·라벨 분포 표.
3. **kNN 라벨 일관성**: 임베딩 kNN(k=10) 이웃의 라벨 다수결/평균과 본인 라벨 차이가 큰 샘플 = 라벨 노이즈 후보(회귀면 |y−이웃평균|/이웃std). 교차검증 내부에서만 계산.
4. 품질 공간 군집과 결함 라벨이 강하게 겹치면 도메인 누수(모델이 장비를 학습) 의심 → 군집 단위 GroupKFold로 재평가해 성능이 크게 떨어지면 확정.
5. 결과물: 의심 샘플 리스트 + 갤러리 → 사람 재판정 → 라벨 수정 전/후 엄밀 CV 비교.
